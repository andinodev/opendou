

Este es uno de los desafíos de ingeniería de bajo nivel más fascinantes. En proyectos complejos como *Crónicas de Jesika*, depender de los archivos `.wav` u `.ogg` sueltos obliga al sistema operativo a realizar miles de aperturas de archivos (*File Handles*), lo que fragmenta la memoria y causa *stuttering* (tirones) durante el juego.

La solución estándar en la industria es compilar todo en un único archivo monolítico (`.bank`) y dividir el audio en dos fases físicas: **Prefetch** (RAM) y **Stream** (Disco).

Aquí tienes el diseño arquitectónico en C++ (GDExtension).

---

El archivo `.bank` debe diseñarse para ser leído secuencialmente de un solo golpe (o usando mapeo de memoria `mmap`). Evitaremos cualquier tipo de asignación dinámica de memoria (`new` o `malloc`) durante la lectura.

#### 1. Estructura del Archivo Binario

Para garantizar la alineación de memoria y evitar padding (relleno basura) por parte del compilador C++, empaquetamos las estructuras.

```cpp
#pragma pack(push, 1) // Desactiva el padding del compilador

struct BankHeader {
    char magic[4];                 // 'S', 'B', 'N', 'K'
    uint32_t version;              // Versión del empaquetador (ej. 1)
    uint32_t num_streams;          // Cantidad de sonidos contenidos
    uint32_t prefetch_block_size;  // Tamaño total de la RAM a reservar
    uint64_t stream_block_offset;  // Dónde empieza el audio de disco
};

struct StreamMetadata {
    uint32_t stream_id;            // Hash StringName del nombre (ej. "Rifle_Fire")
    uint16_t codec;                // 0 = PCM, 1 = ADPCM, 2 = Vorbis
    uint16_t channels;             // 1 (Mono), 2 (Stereo)
    uint32_t sample_rate;          // ej. 44100
    
    uint32_t prefetch_offset;      // Offset relativo dentro del Bloque de Prefetch
    uint32_t prefetch_length;      // Bytes precargados (ej. 64 KB)
    
    uint64_t disk_offset;          // Offset absoluto dentro del archivo .bank
    uint64_t disk_length;          // Tamaño restante en disco
};

#pragma pack(pop)

```

#### 2. Carga Inicial (El Gestor de Bancos)

Cuando el juego invoca `BankManager.load_bank("armas.bank")`, el motor realiza lo siguiente:

1. Lee el `BankHeader`.
2. Lee el array de `StreamMetadata` (la tabla de contenidos).
3. Hace un solo `malloc()` (o redimensiona un `PackedByteArray` en Godot) del tamaño exacto de `prefetch_block_size`.
4. Vuelca el bloque completo de prefetch en la RAM en una sola operación I/O.
5. Mantiene un `FileAccess` abierto apuntando al archivo para las futuras lecturas de streaming.
