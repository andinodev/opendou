Este es el componente que separa a un motor de audio de nivel *indie* de una herramienta AAA. La capacidad de conectarse al juego en ejecución desde un editor externo para mezclar volúmenes, ajustar curvas RTPC o monitorear el rendimiento en tiempo real reduce el tiempo de iteración a cero.

En GDExtension, este sistema requiere un hilo de red dedicado (para no bloquear el juego) y un diseño de paso de mensajes seguro (*thread-safe*) hacia el hilo de audio.

### `TASK-012`: Servidor TCP de Sincronización en Caliente

Utilizaremos las clases de red nativas de Godot (`TCPServer` y `StreamPeerTCP`), pero envueltas en un hilo secundario para manejar las conexiones asíncronas.

#### 1. Estructura del Protocolo de Red (TLV)

Para evitar la saturación y la fragmentación de paquetes típica de TCP, diseñamos un protocolo binario ligero usando el patrón **Type-Length-Value (TLV)**.

```cpp
enum LiveMessageType {
    MSG_HANDSHAKE = 0,
    MSG_UPDATE_VOLUME = 1,
    MSG_UPDATE_RTPC_CURVE = 2,
    MSG_TRIGGER_EVENT = 3,
    MSG_TELEMETRY_DATA = 4
};

// Cabecera estándar de cada paquete (8 bytes en total)
#pragma pack(push, 1)
struct NetworkHeader {
    uint8_t magic[2] = {'G', 'A'}; // "Godot Audio"
    uint16_t message_type;
    uint32_t payload_length;
};
#pragma pack(pop)

```

#### 2. El Servidor y el Bucle de Red

El servidor escucha en un puerto específico (ej. `3016`) y acepta un único cliente (la herramienta de edición).

```cpp
class LiveUpdateServer : public Node {
    GDCLASS(LiveUpdateServer, Node)
private:
    Ref<TCPServer> tcp_server;
    Ref<StreamPeerTCP> editor_client;
    
    Thread network_thread;
    std::atomic<bool> thread_running{false};
    
    // Cola segura de comandos hacia el hilo principal
    SafeQueue<NetworkCommand> command_queue;

public:
    void start_server(int port = 3016) {
        tcp_server.instantiate();
        tcp_server->listen(port);
        
        thread_running = true;
        network_thread.start(_thread_function, this);
    }
    
    static void _thread_function(void* p_userdata) {
        LiveUpdateServer* server = (LiveUpdateServer*)p_userdata;
        
        while (server->thread_running) {
            // 1. Aceptar nueva conexión si no hay cliente
            if (!server->editor_client.is_valid() && server->tcp_server->is_connection_available()) {
                server->editor_client = server->tcp_server->take_connection();
            }
            
            // 2. Leer datos si el cliente está conectado
            if (server->editor_client.is_valid() && server->editor_client->get_status() == StreamPeerTCP::STATUS_CONNECTED) {
                server->poll_client();
            }
            
            OS::get_singleton()->delay_usec(10000); // Descansar 10ms
        }
    }
    
    void poll_client() {
        int available = editor_client->get_available_bytes();
        if (available >= sizeof(NetworkHeader)) {
            // Leer cabecera
            NetworkHeader header;
            editor_client->get_data((uint8_t*)&header, sizeof(NetworkHeader));
            
            // Leer payload basado en el payload_length
            PackedByteArray payload;
            payload.resize(header.payload_length);
            editor_client->get_data(payload.ptrw(), header.payload_length);
            
            // Encolar comando para que el Hilo Principal lo ejecute
            command_queue.push(NetworkCommand(header.message_type, payload));
        }
    }
};

```

#### 3. Aplicación Segura de Cambios

En el hilo principal (`_process`), el gestor revisa la `command_queue`. Si hay un comando para actualizar un volumen, modifica el `AudioEventDef` en RAM. Como todos los `EventInstance` referencian a ese mismo recurso, el cambio de mezcla se aplica instantáneamente en el siguiente fotograma para todas las voces activas.
